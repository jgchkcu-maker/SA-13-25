# Изменения расписания АК · СА-13-25

Бот скачивает фотографии из [публичной страницы «Расписание АК»](https://t.me/s/timetable_of_ak_sibsau),
распознаёт таблицы через Gemini и присылает изменения **только для СА-13-25** в учебную группу.
Личный Telegram-аккаунт не используется: Telethon, `TELEGRAM_SESSION`, `TELEGRAM_API_ID`
и `TELEGRAM_API_HASH` удалены из запуска и зависимостей. Локальный `.env` для GitHub не нужен.

GitHub Actions проверяет канал каждые 20 минут. Компьютер можно выключать.
Сбор уже настроен **с 18 октября 2026 года, 00:00 по Красноярску (UTC+7), включительно**.
Это дата публикации поста. Дата изменений расписания читается отдельно с таблицы.

## Запуск через GitHub

В **Settings → Secrets and variables → Actions → New repository secret** нужны четыре Secrets:

| Name | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | Числовой ID учебной группы, включая минус |
| `GEMINI_API_KEY` | Ключ из [Google AI Studio](https://aistudio.google.com/api-keys) |
| `STATE_ENCRYPTION_KEY` | Отдельная случайная строка для шифрования состояния |

Необязательно: `TELEGRAM_THREAD_ID` — ID темы, если сообщения нужны в конкретной теме форума.
GitHub token создавать не нужно: используется автоматический `GITHUB_TOKEN`.

Создайте ключ состояния в менеджере паролей (минимум 32 случайных символа) или однократной
командой PowerShell, без заполнения `.env`:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните ключ у себя. **Не меняйте и не теряйте его после первого запуска**:
без ключа бот не прочитает историю отправок. Это отдельный ключ, не Telegram-сессия.
Старые Secrets `TELEGRAM_SESSION`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` можно удалить.
Удаление Secret не завершает старый сеанс аккаунта: это делается в Telegram → Настройки → Устройства.

### Получить ID группы без сессии

1. Добавьте бота в учебную группу и разрешите ему отправлять сообщения. Администратором делать не нужно.
2. Добавьте Secret `TELEGRAM_BOT_TOKEN`.
3. **Actions → Schedule watcher → Run workflow → operation: chat-id**.
4. В течение пяти минут напишите в группе `/chatid@имя_вашего_бота`, подставив username бота.
5. Бот ответит ID в самой группе. Скопируйте его в Secret `TELEGRAM_CHAT_ID`.

Для `chat-id` нужен только токен бота. ID и переписка группы не выводятся в публичный лог Actions.
Операция ждёт команду до пяти минут. Не запускайте другой обработчик `getUpdates` или webhook
с этим же токеном. Если команда не дошла или ожидание истекло, отправьте её снова и повторите `chat-id`.

### Начать сбор

После заполнения четырёх обязательных Secrets откройте **Actions → Schedule watcher → Run workflow**,
в ветке `main` выберите **operation: run**. При первом запуске состояние создаётся автоматически.
Бот проверит все доступные посты начиная с 18 октября и отправит найденные изменения.
Затем проверки продолжатся каждые 20 минут. `initialize` оставлен как необязательная операция
создания пустого состояния без отправки; повторно запускать её для существующего состояния не нужно.

Дополнительные **Variables** (уже настроены по умолчанию):

| Variable | По умолчанию |
|---|---|
| `TELEGRAM_SOURCE` | `@timetable_of_ak_sibsau` |
| `START_DATE` | `2026-10-18` — с начала суток по Красноярску |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` |

Дата фиксированная, не «последние три дня»: даже при более позднем запуске сбор начнётся с 18 октября.
Если уменьшить `START_DATE`, более ранние посты добавятся при следующей проверке; история отправок сохранится.

## Обработка фотографий и правок

- Все доступные фотографии каждого альбома скачиваются и передаются Gemini вместе.
- Каждая проверка перечитывает всю публичную историю от `START_DATE`, с переходом по страницам.
  Это позволяет заметить правки старых постов, включая те, в которых группы сначала не было.
- Изменения определяются по тексту, составу альбома и SHA-256 фотографий.
  Временные CDN-ссылки не считаются содержимым: их смена не вызывает повторный OCR.
- Фотографии скачиваются для сравнения при каждом запуске; неизменившиеся повторно не распознаются.
- Новым публикациям даётся 120 секунд для завершения загрузки альбома.
- Gemini возвращает структурированный JSON; Python дополнительно проверяет строки.
- Ищется СА-13-25, включая сокращение `СА-13` без года. Допустимы `СА 13 25`, `СА1325`,
  `СА-13/25`, `СА 13`, `СА13`, латинские `CA`, скобки, точки и разные тире.
  Явно указанный другой год (например, `СА-13-24`) исключается.
  При обновлении правил группы ранее просмотренные фотографии проверяются заново один раз;
  история отправленных сообщений сохраняется для защиты от дублей.
- Найденные строки проходят отдельную повторную проверку по тем же исходным фотографиям.
  Модель прослеживает границы ячеек с учётом наклона таблицы и заново читает преподавателя
  и кабинет, не видя первоначально распознанных значений. Нечитаемый преподаватель остаётся
  пустым; заполненная фамилия должна присутствовать в дословной транскрипции строки.
- Извлекаются дата изменений, пара, предмет, преподаватель, кабинет. Нечёткие отдельные поля
  отмечаются как неразборчивые; неясная группа, дата или пара — строка пропускается.
- Если группы нет, бот молчит. Неразборчивые посты повторно распознаются через 6 часов,
  максимум три попытки на версию; правка источника начинает новый цикл попыток.
- Дубли исключаются по нормализованным строкам, включая повторные публикации.
- После правки источника бот редактирует своё сообщение. Если данные исчезли/не читаются,
  прежнее уведомление помечается как неподтверждённое, без утверждения об отмене занятий.

Модель API: [`gemini-3.5-flash-lite`](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).
Доступность модели и квоты конкретного ключа проверяются реальным запуском.

Сообщения используют HTML Telegram: жирные заголовки даты и пары, моноширинный кабинет,
пустые строки и ссылку на источник без предпросмотра. Эмодзи и стикеров нет.
Длинные результаты делятся на части в пределах лимита Telegram.

## Ограничения публичного источника

Читается HTML `t.me/s`, не официальный API истории канала. Если Telegram изменит разметку
или ограничит публичный просмотр, загрузчик потребуется обновить. Приватные каналы недоступны.
Скачиваются изображения веб-просмотра: они могут быть меньше оригиналов в приложении.
Скрытые вложения и оригинальное разрешение получить этим способом нельзя. Если в выбранном посте
обнаружено неподдерживаемое вложение, сбор останавливается и курсор не продвигается.

У публичной страницы нет надёжной даты редактирования: пауза 120 секунд относится к публикации,
а правки выявляются сравнением содержимого при следующем запуске. Полное удаление поста
не считается подтверждением отмены занятий и не отменяет ранее отправленное уведомление.
OCR вероятностный, нечёткие таблицы могут быть пропущены. Каждое уведомление содержит ссылку на оригинал.
Количество HTTP-запросов растёт вместе с историей от заданной даты.

GitHub может задерживать/пропускать cron-запуски при нагрузке и отключать расписание
в неактивных публичных репозиториях. Следующая успешная проверка перечитывает доступную историю.
20 минут — интервал планировщика, не гарантия точного времени доставки.
См. [ограничения schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Состояние и восстановление

Состояние хранится в ветке `bot-state`, зашифрованной AES-GCM отдельным `STATE_ENCRYPTION_KEY`.
В публичном репозитории не видны ID учебной группы и тексты уведомлений. Ключей API и фотографий
в состоянии нет. Фото временные; крупные альбомы временно загружаются через Gemini Files API
и затем удаляются. Логи не содержат ключей, сырых ответов OCR и переписки группы.

Автоматически создаётся только отсутствующая ветка состояния. Если существующая ветка повреждена,
`state.json` потерян или ключ не подходит, бот останавливается: история не сбрасывается.
При переходе со старого загрузчика сохраняются слоты уведомлений для известных ID публикаций.
Изменение целевого чата/канала не переносит автоматически отправки в другой чат.

Перед каждой отправкой сохраняется намерение, после ответа Telegram — ID сообщения.
У `sendMessage` нет ключа идемпотентности: потеря ответа после принятия сообщения даёт
неоднозначный результат. Бот останавливается с `pending`, не отправляя возможный дубль.
Правки с известным ID повторяются безопасно.

Восстановление:

1. Проверьте последние сообщения бота в учебной группе.
2. **Actions → Schedule watcher → Run workflow → operation: resolve**.
3. Если сообщение доставлено, укажите ID в `delivered_message_id` (последнее число ссылки
   на сообщение в супергруппе), оставив `confirm_not_delivered` выключенным.
4. Только если сообщения действительно нет, включите `confirm_not_delivered`, оставив ID пустым.
5. Запустите `operation: run`. Не удаляйте состояние ради восстановления.

Не отменяйте workflow во время отправки, не удаляйте сообщения бота вручную.
Параллельные запуски сериализованы. Для переноса состояния сохраните прежний ключ шифрования.

## Локальная разработка

Для обычной работы достаточно GitHub Secrets и Actions. Для локальной разработки нужен Python 3.12/3.13:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
Copy-Item .env.example .env
```

После заполнения локальных ключей: `.\.venv\Scripts\schedule-bot.exe run`.
Команда действительно отправляет сообщения — используйте отдельный тестовый чат.
Не запускайте локальный и GitHub экземпляры с разными состояниями в одну группу.
`.env`, `*.secret`, старые сессии, `.venv` и `state` исключены из Git.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check .
```

Тесты используют подставные API, не отправляют сообщения. Проверяются пагинация, граница даты,
альбомы, правки фото/подписей, смена CDN-ссылок, ошибки HTML/медиа, фильтрация, форматирование,
доставка, восстановление и шифрование. CI — Python 3.12/3.13. Зависимости зафиксированы в `requirements.lock`.
